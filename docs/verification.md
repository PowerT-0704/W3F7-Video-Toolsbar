| 检查 | 结果 |
| --- | --- |
| 动效与排版 | 核对深浅主题的标识动效、8 秒循环衔接、变速曲线、最小化暂停和减少动效。封面可以放大，750 px 窄窗的工具布局为单列 |
| 播放与抽帧 | 从解压后的便携版用原样片检查拖动播放头、播放、暂停、键盘跳到末帧、PNG 导出与设为封面。用 MPEG-4 测试素材验证 FFmpeg 逐帧回退 |
| 缓存迁移与清理 | 用含中文和空格的 E 盘目录验证从 C 盘迁移、重启记忆、恢复默认和清理。迁移后当前帧和生成的封面继续可用。清理保留正在使用的缓存及测试用户文件 |
| 缓存故障 | 目标路径不可用或设置写入失败时原目录仍可用。另测启动时自定义位置缺失，回到系统临时目录并提示 |
| 成片哈希 | 用 7.917 秒处的帧封装原样片。另存 PNG 与成片附图的 SHA-256 均为 `8cc5f2b51e9f1d919f92f0ac863ee4d75de4e1721bee839f11e50c8b71e2e636`。各音视频流哈希与原样片一致，时长为 41.621333 秒，时间码为 00:02:16:35 |
| 欢迎、环境与更新检查 | 验证首次欢迎、重启状态、Windows 减少动效提醒和 FFmpeg 的 PATH、手动配置及缺失三种情况。启动和手动查询均识别公开的 v1.0.0 低于本地 v1.1.0 |
| 构建与安装 | 通过类型检查和生产构建。Windows x64 便携 ZIP 解压运行通过。安装版在中文和空格路径下安装、启动、读取样片和定位通过，卸载后移除注册项及开始菜单入口 |

## 复查成片

对原视频和验收视频各执行一次逐流哈希检查。对提取的图片使用 PowerShell 的 `Get-FileHash -Algorithm SHA256` 比较原封面。

```powershell
ffmpeg -v error -i input.mp4 -map "0:V" -map "0:a?" -c copy -f streamhash -hash SHA256 -
ffprobe -v error -show_streams -show_chapters -of json output.mp4
ffmpeg -v error -i output.mp4 -map "0:v:disp:attached_pic" -c copy -frames:v 1 -update 1 extracted.png
```

其他 Windows 环境可在资源管理器的大图标视图中复查。社交地址按用户提供的链接配置。
